## Rules / Preferences (directives)

User preferences are written as dated directives — one per entry, imperative phrasing (`Always`, `Never`, `Prefer`), each with an observed date and `active`/`superseded` status. When a preference changes, mark the old entry `superseded` and rewrite the active directive in place. Never leave contradictory active directives.

<!-- observed: YYYY-MM-DD | status: active -->

- Prefer ...

<!-- observed: YYYY-MM-DD | status: superseded -->

- Prefer ... (old phrasing, kept for history only)

## Action context (optional)

When a memory changes future behavior, capture when it is safe to act — not just the fact.

- **Source / Owner:** _(who said it or owns the decision — affects trust)_
- **Action when:** _(condition or timing under which it applies)_
- **Expires:** _(date or event that ends it, or what unlocks action)_
